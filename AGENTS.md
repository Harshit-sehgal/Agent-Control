# AGENTS.md

Guidance for agents (and humans) changing this repo. Any `CLAUDE.md` still applies; this file is the project-level contract.

## What this is
Local-first, **zero-npm-runtime-dependency** personal bot platform with human-approved actions. Node `>=22` (`.nvmrc`).

- `shared/` — code used by **both** the browser UI and the Node server. Must stay browser-safe (no Node builtins). The chats UI is split into `shared/ui-*.js`: `ui-kit.js` (string builders: icons, rows, round and switch buttons, time labels), `ui-model.js` (pure view models: needs-you count, thread timeline, routes), `ui-company.js` (pure: bot rows, thread rows, the progress pill, handoffs, the hash routes), `ui-feed.js` (pure: what a conversation shows, in order), `ui-face.js` (a bot's face as one inline svg), `ui-store.js` (single state object, API wrapper, navigation), `ui-chat.js` (what happens after send), `schedules.js` (pure: how often and when in words, a bot's queued schedules, the task body a schedule card posts), `ui-shell.js` (the desktop sidebar, the phone chrome and home, search, the page frame), `ui-conversation.js` (a bot chat or a thread: header, feed, cards, composer) with `ui-attach.js` (the composer's attach button, paste, drop and file chips), `ui-profile-model.js` (pure view models for the profile, Edit, New bot, Settings and Company), `ui-profile.js` (a bot's profile, Edit, the New bot page and the options menu), `ui-settings.js` (Settings, the Company chart and Activity), `ui-asks.js` (pure: the ask card, each bot's permission rows, a bot's permissions in plain words (`permissionSummary`) and the pause banner), `presets.js` (pure: the Careful, Balanced and Hands-off safety presets, which one is on, and the Undo snapshot they return), `ui-reorder.js` (pure: what a pin or drop does) with `ui-gestures.js` (drag, long press, right-click and Alt+arrows on the Chats home), `app-catalog.js` (pure: the Connect apps catalogue, its search and categories, and the connector request each app makes), `ui-sheets.js` (sign-in and password sheets), `ui-connect.js` (Settings → Connectors markup) with its pure rules in `ui-connect-model.js`, `ui-computer.js` (pure: a bot's Computer view input and scaling rules) with `ui-computer-view.js` (that view: page picture, Take over, Hand back), `ui-takeover.js` (a person driving the page a bot asked for), `ui-push.js` (push notifications on this device), `message-search.js` (pure: search message text in every bot chat and thread of the snapshot, and the marked snippet a result shows), `briefing.js` (pure: the daily briefing's schedule body and the facts its run is handed, from real state), `templates.js` (the built-in task templates and the owner's saved ones, `state.templates`, `POST/DELETE /api/templates`) with `ui-templates.js` (their chips, the composer's Templates sheet and the briefing sheet), `ui-admin.js` (admin pages), `ui-dialogs.js` (toast, sheet, confirm/ask), `ui-fx.js` and `ui-actions.js` (action and form lookup tables), `usage.js` (pure: token and cost bookkeeping, prices, the month by bot and the words a run's usage shows). Three stylesheets load in order: `app.css` (tokens, forms, sheets), `shell.css` (the sidebar, phone chrome, chats and gestures) and `profile.css` (profile, Settings, New bot, Company, Activity). Per-person choices (pins `ac-pins`, order `ac-order`, hidden `ac-hidden`) live in `localStorage` through `saveLocal` and are never sent to the server. What may be attached to a message (types read from the bytes, 10 files, 10 MB each; a model request gets images up to 5 MB each and 15 MB in all, and a bigger one is named to the model instead) lives in `shared/attachments.js`; a message carries only `attachments` references. Conversation history rules live in `shared/chats.js` and bot/group settings rules in `shared/bot-settings.js`; both transports use them. Model text may only add run recipients through `handoffTargets` in `shared/coordination.js`. How far a run may go lives in `shared/limits.js`: no limits by default (`state.limits`, Settings → Permissions → Limits, `POST /api/limits`), a `BACKSTOP` that always applies, and `FAIL_STREAK` failed rounds in a row stop a run and notify the owner. `ui-model.js`, `ui-kit.js`, `ui-company.js`, `ui-feed.js`, `ui-profile-model.js`, `ui-asks.js`, `ui-reorder.js`, `ui-connect-model.js`, `ui-computer.js` and `message-search.js` must stay pure (no DOM, no globals) because Node tests import them. A run's decision ritual and its log-watching loop live in `shared/run-follow.js` over injected pieces, so `ui-chat.js` is only the store adapter. The Pages demo runs its group coordination behind the same routes the server serves (`GET/POST /api/groups/:group/chat`, `runs/:run/continue|plan|cancel`) and keeps runs in the workspace snapshot; that offline engine lives in `shared/local-api.js`, so the UI never branches on the build to drive a run.
- `src/` — Node-only: server, stores, auth, queue, scheduler, AI client, local agent, vault. `server.js` only opens the store, installs `crash-guard.js` (a stray rejected promise is logged, not fatal), wires the services into `src/app.js` and listens; `app.js` owns the request dispatcher and the per-workspace start-up, so it can be imported (and tested) without binding a port. API routes live in `src/routes-*.js` and are registered through `src/router.js` with the access each one needs (`public`, `agent`, or a least role). Add a route there, never as a branch in `app.js`. A route handler uses `c.store`, the store of the session's workspace (`src/workspaces.js` keeps one database per workspace); only accounts, sessions, memberships and push subscriptions live in the first workspace's store. Attached files live in their workspace's `attachments` table (`src/attachments.js`, `src/routes-files.js`); a route that answers with a `Buffer` sends those bytes with its own headers. A bot turn hands its executor a fourth argument `{readFile}` (`src/bot-turn.js`), and `src/ai.js` turns the owner's newest files into each wire's image parts (`userContent`).
- `docs/` — the GitHub Pages bundle. JS/CSS/HTML copied from `shared/` are generated (`npm run build:pages`); hand-written markdown in this folder is edited in place.
- `agent/` — the local device process.
- `tests/` — `node --test`. `docs/BUILD-PLAN.md` tracks the roadmap phases.

## Commands — every change must leave these green
- `npm run check` — syntax-check every source file (`node scripts/check.mjs` walks `src/`, `shared/`, `agent/`, `scripts/`).
- `npm test` — unit/integration tests.
- `npm run build:pages` — regenerate `docs/` from `shared/`.
- `npm run test:coverage` — tests with V8 coverage.
CI (`.github/workflows/ci.yml`) runs `check`, `test`, and a **docs-drift** check (re-builds and fails if `docs/` is stale).

## Hard invariants (each is enforced by a test — do not work around them)
1. **Asset registry.** Every module reachable from the `index.html` scripts (`app.js`, `local-api.js`, `transport.js`) must be listed in `shared/assets.js`. Miss one and the served UI dies on a bare 404. → `tests/assets.test.js`.
2. **Syntax coverage.** Every file under the `check` script's roots must be walked by `scripts/check.mjs`. → `tests/check-coverage.test.js`.
3. **No docs drift.** Copied UI assets in `docs/` are generated. Edit `shared/`, then `npm run build:pages`; CI + `tests/pages-bundle.test.js` fail otherwise. Hand-written markdown in `docs/` is edited in place.
4. **CSP parity.** The `Content-Security-Policy` meta in `shared/index.html` must equal `META_CSP` in `shared/core.js`, which is the `CSP` header value minus `frame-ancestors 'none'` (a meta tag cannot carry that directive; the header does). → `tests/security-headers.test.js`.
5. **Module graph.** `shared/` may not import a `node:` builtin, `../src/`, or read `process.env`; no relative import may form a cycle; every `src/` module must be reachable from `src/server.js`; and every `TABLE_SHAPES` entry must match the table it writes. → `tests/architecture.test.js`, `tests/store-incremental.test.js`.

## Adding a shared module (the #1 source of regressions)
1. Create `shared/<name>.js` (browser-safe).
2. Add `'<name>.js'` to `shared/assets.js` — the one list read by both `scripts/build-pages.js` and `src/app.js`.
3. `npm run build:pages`.
`tests/assets.test.js` walks the import closure, so step 2 cannot be forgotten silently.

## Working alongside other agents
More than one agent may edit this tree at the same time. To stay safe:
- Prefer **small, additive, scoped** changes; avoid whole-file rewrites of "hot" files.
- Never `git add -A` or commit another agent's half-finished work — stage only your own files.
- When unsure, add a **new** file/test instead of editing a file that is mid-change.
- Re-run `check` + `test` immediately before you finish, and leave the tree green.

## Security
- `.env` is git-ignored and loaded at startup by `src/env.js`. **Never commit or print secrets.** Set `AGENT_SKIP_DOTENV=1` to ignore it (tests do this).
- AI providers are the environment (`AI_BASE_URL`, `AI_API_KEY` or `OPENAI_API_KEY` / `ANTHROPIC_API_KEY` / `GEMINI_API_KEY`, `AI_MODEL`, `AI_API_STYLE` `chat` | `responses` | `anthropic` | `gemini` | `azure`, `AI_TIMEOUT_MS`) plus saved BYOK providers in the workspace vault (**Settings → Models and keys**). Five wire shapes are spoken (`shared/ai-presets.js` is the one list of protocols and provider presets): OpenAI chat completions, OpenAI responses, Anthropic Messages, Google Gemini and Azure OpenAI. Azure takes the resource endpoint plus an API version, and its model id is a deployment name; custom request headers are stored as a vault credential like the key. Saving a provider reads that provider's own model catalogue with the pasted key, so the picker offers models the key can use; `PATCH /api/ai/providers/:id` renames, re-points or rotates the key. Effort (`EFFORT_LEVELS` in `shared/ai-presets.js`: low, medium, high, or empty for none) is saved as `ai.defaultEffort` and `ai.bots[id].effort` through the same two PATCH routes; `src/ai.js` and `agent/cli-model.mjs` spell it per wire and retry once without it when a provider names it in a 400. A provider, MCP or MCP sign-in address on a private, link-local or metadata network is refused (`src/reach-guard.js`; loopback is allowed for local models, `AGENT_ALLOW_PRIVATE=1` lifts it). Saved providers, MCP servers and their sign-in servers are reached only through `guardedFetch`, which resolves the name once, checks every address and connects to the checked one (Host and TLS name unchanged, redirects not followed), so a name rebound after the check is never used; the environment's own `AI_BASE_URL` is the operator's and is fetched as is, and moving a saved provider to another origin needs the key again. A key is never returned and never printed. Never commit or print keys.
- Model output never gets publication/filesystem tools: a send, post or submit happens only through the ask mechanism, which the **owner** decides per bot and per site (Ask each time by default, Always allow if they choose). Every bot has basic access with no grant: it may open a web page and read a connected app (`BASIC_ACCESS` in `shared/asks.js`), unless the owner set that site or account to Ask each time or Deny, or switched **Browse and read without asking** off (`state.askBasics`, `POST /api/permissions/basics`). An Always allow may carry an end (`until`: for 1 hour or for today, chosen on the ask card); past it the grant is no answer, so the bot asks again, and `sweepGrants` drops it on load. The owner-only `POST /api/permissions/preset` applies a safety preset (`shared/presets.js`) and `POST /api/permissions/restore` puts back the Undo snapshot that route or an Always allow answer returned. Hands-off (`state.handsOff`) lets a send, a post or a connector write with no rule go without asking on every site; it is one switch, never a per-site grant, so payments and deletes still ask and an every-site payment Always allow still cannot exist. The first-run checklist (`setupChecklist` in `ui-profile-model.js`) is ticked from real state; hiding it (`ac-setup`) and having opened Permissions (`ac-perm-seen`) are per-person `saveLocal` choices. Once a run has read connector data, a page on a site with no Always allow asks again, so read data cannot be carried off in an address. Everything else (send, post, delete, connector writes) shows an ask card (Decline / Allow / Always allow for this bot) unless a grant already says Always allow, and a paired local agent runs the page (`shared/asks.js`, `shared/bot-browser.js`, `src/bot-browser.js`). Grants are per bot, per action and per site or account; a payment asks every time unless the owner sets Always allow for one bot on one site (the card and Settings confirm it first; a payment Deny with no site covers every site, and an every-site Always allow is refused and swept). The per-bot permission checkboxes and `browserApproval` have no UI. X and Twitter are ordinary sites: bots may click and type there, and a click on Post asks like any post. A human check (CAPTCHA) is never solved by a bot; it is handed to the owner.
- Usage and cost: `src/usage.js` meters every model call inside a bot turn (`meterTurn`, AsyncLocalStorage) and records tokens per run (`run.usage`) and per bot per UTC day (`state.usage`, kv `usage`, 62 days); the pure rules are `shared/usage.js`. A cost is computed only from prices the owner typed on a saved provider (`prices` on `PATCH /api/ai/providers/:id`, input / output / optional cached-input dollars per million); the app never ships or guesses prices, and a `local-cli` call is "included in subscription". The fallback model (`ai.fallback`, `PATCH /api/ai`) answers a turn once when `fallsBack(error)` in `src/ai.js` says the failure is the provider's (429, 5xx, timeout, network, 401/403, quota, CLI limits), after the primary's own retry; it never chains and never retries a 400. Anthropic bodies carry at most two `cache_control` breakpoints (system, the envelope's stable head) and `createEnvelope` keeps its stable keys first; keep both byte-stable (no per-turn values before them). A page is handed over in `PAGE_EXCERPT_CHARS` parts (`"part"` in a browser request, `MAX_PAGE_PARTS`).
- Connect apps signs in to an app's official MCP server where it allows self-registration (`oauth` in `shared/app-catalog.js`, `src/mcp-oauth.js`: RFC 9728/8414 discovery, RFC 7591 registration, PKCE, `resource`); the tokens are one vault credential with the address and are renewed in `mcpTarget`. An app without it signs in through the shared browser (`kind: 'site'`). A bot that opens a connected app's own site is sent back once per task to use the connector (`connectedVia` in `shared/bot-browser.js`).

## Coverage notes
`npm run test:coverage` uses V8 coverage, which only counts files the test process imports. The browser-only files (`shared/app.js`, the DOM-bound `shared/ui-*.js` modules (the shell, conversation, profile, settings and gestures among them), and `shared/transport.js`) therefore show as *absent*. They are exercised by the Playwright smokes (`tests/polish_smoke.py`, `tests/usability_smoke.py` via `npm run test:ui`, and `tests/live_smoke.py` via `npm run test:e2e`), which are not part of `node --test`. `shared/ui-model.js` and `shared/ui-kit.js` are imported by Node and are covered by `node --test`.
